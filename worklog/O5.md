# O5 — 2026-11-20

NervaOrg/nerva#5 (fixes #1): the documents feed read an op larger than `limit` in requests of
`limit` each, so `limit=1` cost thousands of round trips and timed out `test:api` on a loaded
host (NRV-E0606). Now `limit` sizes the first request and the rest of the op is read in the largest
requests (O5). New unit test counts the requests; `check`, `test:fmt`, the `documents` unit filter
and the full `test:api` pass.

Review fix: the large request that ends an op no longer lets later ops onto the page: it is cut at
the first change of another op (`more` true), so `limit` bounds a page as before. Tests check each
page (whole ops, first op plus at most `limit - 1` changes), requests per page, and the op of
`changes_per_op_max` changes; `FeedClient` answers as `execute_get_changes`.
