# O5 — 2026-11-20

NervaOrg/nerva#5 (fixes #1): the documents feed read an op larger than `limit` in requests of
`limit` each, so `limit=1` cost thousands of round trips and timed out `test:api` on a loaded
host (NRV-E0606). Now `limit` sizes the first request and the rest of the op is read in the largest
requests (O5). New unit test counts the requests; `check`, `test:fmt`, the `documents` unit filter
and the full `test:api` pass.

Review fixes: pages are byte-identical to the previous loop's for the same cursor and `limit`
(`limit` windows; the last window ends `limit * (n / limit + 1)` changes from the page start, `n`
the first op's length); only the number of requests changed, bounded by `3 + ceil(first op
changes / changes_request_max)` per page. A differential test runs that previous loop as a model
over random feeds, limits and cursors, with the reviewer's cases as explicit tests; tests also
check each page's request bound, the op of `changes_per_op_max` changes, and the empty feed.
`FeedClient` answers as `execute_get_changes`. O5's area is the one the other API decisions use.
