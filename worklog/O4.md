# O4 — 2026-11-20

NervaOrg/nerva#4: CI on a self-hosted Woodpecker (ci.botpike.com) beside GitHub Actions. Jobs are
plain `ci/` scripts both engines call; Woodpecker steps run as an unprivileged `ci` user, split
`check` into `check-code`, `check-scripts` and `check-packages`, and the sim-fleet yields CPU and IO
to CI. Adds the Woodpecker and Forgejo bootstrap scripts (Forgejo pull-mirrors every 5 minutes).

Review fix 1: Woodpecker cancelled the pipeline for this branch's code commit when the worklog
commit arrived, and the worklog push then skipped as docs-only, so the PR showed green without
running anything. `ci/changes.sh` now skips only when the branch's previous pipeline succeeded
(`CI_PREV_PIPELINE_STATUS`) and was itself a push, with a table test (`ci/changes_test.sh`).

Review fix 2, decision O4 (`docs/decisions/O4-self-hosted-ci-trust.md`):

- No step is privileged. The box's Docker daemon gets Docker's default seccomp profile plus the
  io_uring syscalls (`ops/ci/docker/`), installed by `woodpecker-bootstrap.sh`; the owner's one-time
  step is running it (README, "Nerva on Woodpecker", step 4). `ci/io_uring_check.sh` stays.
- Only a push to main writes shared caches: separate steps by `when:` mount `main/` writable or
  `:ro`; a branch has its own bounded, pruned copy under `branches/`; the toolchain archive is
  named and verified by its sha256 on every use. The branch can still bypass the mounts by editing
  its own YAML (Trusted volumes); the decision says so, and what remains trusted.
- Timeouts: 75 minutes (330 for the long searches) instead of 30, after pipeline 12's
  `check-scripts` and `targets` both hit 30; the package repositories' tests are their own workflow.
- `targets` is `targets-check` then `targets-build`; release builds run on Woodpecker only for a
  push to main, and `ci.yml` saves its cache between the two.
- NRV-E1201 to E1210, W1201, W1202 registered (`docs/ERRORS.md`, 12xx), triggered by
  `ci/ci_test.sh` (except E1203, E1209, E1210, which need a Woodpecker step or a Jepsen run).
- Smaller: the Jepsen output goes through `ci_redact` (Woodpecker masks only secrets it holds); the
  Woodpecker token goes to curl by `-H @file`; the Forgejo password reset goes through the API, not
  the command line; the Jepsen lock wait is bounded; dead helpers removed.

Eleventh review (5999926337): `ci_lock_file` ran as root on a path inside a directory `ci` owns, and `: >>`, `chown` and `chmod` follow symlinks, so a job could plant `branches/.lock -> <anything>` (the Docker socket, `main/tools`) and every later root step chowned and chmodded the target to root 0600: a root confused deputy. Eighteenth review (design change, with 4649594323, 4649595082, 4649595593, 4649595898): the mount roots are never job-writable, and the job's own tree is normalized by the job.

Design as built. (1) `main/`, `branches/` and `jepsen/` are root-owned, mode 0755, with no ACL. `nerva-woodpecker.sh host` makes them so and makes no child; every step checks its roots (`ci_mount_root`) and repairs one (W1203) or refuses (E1229). Root makes the direct children itself, `mkdir -m 0755` and `chown -h` (`ci_child_make`), so no job can have swapped one for a link between root's test and root's use: nothing a root operation touches is job-writable. (2) A direct child the job owns and cannot use, of any type (a file, a FIFO, a socket, or a directory whose normalization failed), is removed by root (`rm -rf --one-file-system` of the one name, `ci_child_reset`, W1204) under the lock that keeps the other jobs out and made again; a child another uid owns, or one other jobs hold the lock of, is refused (E1228, or E1214 for a branch's directory that is not a directory) and left as it was. (3) Before the job runs, `ci_normalize` runs as the job over the child the step uses: every directory gets `u+rwx` (`find` acts on a directory before it enters it, so a `chmod 0000` one is opened and then searched), a FIFO or socket is removed, and every directory loses its ACL, default entries included (`setfacl -b -k`). A failed or timed-out (`CI_NORMALIZE_SECONDS`, 600) normalization resets the child. `acl` is installed by the step; NRV-E1233 if `setfacl` is missing.

Deviation, on purpose: a directory with a bad mode (0555, 0600, 0666, 0200, 0000) or an ACL at the child itself is not reset but normalized, silently and with its contents kept, because that is what rule 3 says and it costs the next pipeline nothing; W1204 is for what normalization cannot fix. A branch whose tree could neither be normalized nor reset (other jobs hold the lock) is refused with E1228 rather than run over an unnormalized tree. A branch pipeline mounts main read-only, so damage deep in main's tree is repaired by the next pipeline for main (documented in the cache.sh header and the README).
